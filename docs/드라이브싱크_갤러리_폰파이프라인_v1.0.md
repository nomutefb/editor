> **v1.7 (2026-08-11 · 진범 봉합)**: v1.6이 사유를 싣자마자 로그가 진범을 뱉었다 — `drive-download-20260811T121058Z-1-001.zip: Failed to copy: multi-thread copy: failed to find object after copy: object not found`. **정체** = rclone은 `--multi-thread-cutoff`(기본 **256M**)를 넘는 파일만 여러 갈래로 쪼개 받고, 다 쓴 뒤 대상 객체를 다시 조회해 검증하는데 안드로이드 `/sdcard`는 FUSE 에뮬레이트라 방금 쓴 파일의 즉시 조회가 어긋나 죽는다. **「말짱한데 갑자기」의 답** = 코드·설정·인증 전부 무변경이고 **입력이 바뀐 것** — 평소 사진·영상은 문턱 아래라 단일 스트림으로 조용히 돌았고, 드라이브 웹의 「여러 개 한꺼번에 받기」 산출물이 Shared에 올라온 순간 **그 파일 하나에만** 다른 코드 경로가 켜졌다(v1.6 ⓒ 부분 성공 폐기와 곱해져 3분 영구 반복). 처방 = `--multi-thread-streams 0`(공식 문서 「Set to 0 to disable multi thread transfers」). ⚠ 대안 폐기 = cutoff 상향은 문턱만 미루는 미봉 · `--transfers`는 파일 병렬 수라 이 축과 무관. 짝 = **장부 오염 자동 회수**(`docs/drivesync-fix.sh` ②단 = 로그가 이름을 댄 실패 파일만 로컬 실존 대조 → 없으면 장부에서 뺀다 · 전량 리셋 금지 · `.bak` 선백업).
> **v1.8 + 업로드 v1.3 (2026-08-11 · 운영자 「저런 압축파일은 동기화 안되게 · 양방향 모두」)**: 묶음 파일(zip·rar·7z·tar·gz·tgz·bz2·xz·zst·iso·dmg·apk·exe) **양방향 제외**. 갤러리에 갈 이유가 0이고 실제로 260811 사고의 진범이 `drive-download-*.zip`이었다. ⚠ **셸 축으로 거른다**(rclone `--exclude` 아님) — `--files-from` 목록을 주는 순간 rclone 필터는 우회되므로 **목록을 만드는 자리**에서 빼야 양쪽 다 확실하다(다운 = `lsf` 산출 `$NOW.raw` → `grep -viE` → `$NOW` · 업 = `$UNOW` 조립 직후 같은 `grep`). ⚠ 두 파일의 `EXC_RE`는 **동값 유지**(한쪽만 고치면 반대 방향이 조용히 샌다) · 대소문자는 `-i`가 흡수(`backup.TAR.GZ` 실측 차단) · 늘리려면 그 한 줄에 확장자만 추가.
> **범위**: 이 문서는 **드라이브 → 갤러리 미러링**만 다룬다. 기사 수집 큐(공유 → pending → Actions)는 별도 = `docs/큐파이프라인_폰재구축플레이북_v1.0.md`. 둘은 서로 안 건드리고 한 폰에서 공존한다.

## 0. 전체 구조 (한 장)

```
[PC A]  다운로더(Seal/gallery-dl) ─┐
[PC B]  다운로더(Seal/gallery-dl) ─┤→  Google Drive "내 드라이브/Shared"
                                    │        (드라이브 데스크톱 "내 드라이브 스트림"으로 저장)
                                    ▼
                        ┌───────────────────────────────┐
                        │  폰 Termux: drive-gallery-sync.sh │  ← rclone gdrive:Shared
                        │  (Tasker가 3분마다 + 잠금해제마다 실행) │
                        └───────────────────────────────┘
                                    ▼
                     /sdcard/Pictures/DriveSync  (LOCAL)
                                    ▼
                        termux-media-scan -r  → 갤럭시 갤러리
```

**핵심 불변**
- 폰은 **rclone `gdrive:` = 내 드라이브 루트**만 본다. → PC가 파일을 넣을 곳은 **반드시 "내 드라이브/Shared"**.
- **⚠️ "컴퓨터 백업"(드라이브 데스크톱 백업)에 넣으면 rclone이 못 본다** = 안 내려옴 = "떨어져 나감"(§7 이번 원인). 두 PC 다 **"내 드라이브 스트림"**으로 저장해야 한다.
- Autosync 앱 **안 씀**(실시간 동기화 안 돼서 버림). 순수 **Termux + Tasker**. `.tmp.drivedownload`/`.tmp.driveupload` 폴더가 보이면 옛 Autosync 잔재다(무시·삭제 가능).

## 1. 폰 스크립트 — `~/.termux/tasker/drive-gallery-sync.sh` (전문)

```sh
#!/data/data/com.termux/files/usr/bin/sh
# ── 동기화 제외 칸(운영자 260811 "저런 압축파일은 동기화 안되게 조치해도됨 · 양방향 모두") ──
#   묶음 파일은 갤러리에 갈 이유가 0이고, 실제로 260811 사고의 진범이 드라이브 웹의
#   「여러 개 한꺼번에 받기」 산출물 `drive-download-*.zip`이었다(256M 초과 → 갈래받기 발동).
#   ⚠ **셸 축으로 거른다**(rclone `--exclude` 아님) = `--files-from` 목록을 주는 순간 rclone 필터는
#   우회되므로 목록을 만드는 자리에서 빼야 양쪽 다 확실하다.
#   ⚠ 짝 = `drive-camera-up.sh`의 `EXC_RE` **동값 유지**(한쪽만 고치면 반대 방향이 조용히 샌다).
#   늘리려면 이 한 줄에 확장자만 추가(대소문자는 -i가 흡수).
EXC_RE='\.(zip|rar|7z|tar|gz|tgz|bz2|xz|zst|iso|dmg|apk|exe)$'
REMOTE="gdrive:Shared"
LOCAL="/sdcard/Pictures/DriveSync"
SEEN="$HOME/.drivesync.seen"
NOW="$HOME/.drivesync.now"
NEW="$HOME/.drivesync.new"
MISS="$HOME/.drivesync.miss"
LOG="$HOME/.drivesync.log"
STAMP="$HOME/.drivesync.last"
FAILC="$HOME/.drivesync.lsffail"
CPFAIL="$HOME/.drivesync.copyfail"
STUCK="$HOME/.drivesync.stuck"
STUCK_N=10
VER="v1.8"
T=$(date +%s)
if [ -f "$STAMP" ] && [ $((T - $(cat "$STAMP"))) -lt 120 ]; then exit 0; fi
echo "$T" > "$STAMP"
echo "$VER" > "$HOME/.drivesync.ver"
mkdir -p "$LOCAL"; touch "$SEEN"
[ -s "$SEEN" ] || echo "__init__" > "$SEEN"
if ! rclone lsf -R --files-only --contimeout 15s --timeout 60s --exclude "*.app/**" "$REMOTE" > "$NOW.raw" 2>>"$LOG"; then
  N=$(($(cat "$FAILC" 2>/dev/null || echo 0) + 1)); echo "$N" > "$FAILC"
  if [ "$N" -ge 3 ]; then
    termux-notification --id drivesync-fail -t "드라이브싱크 실패 ⚠️" \
      -c "$(TZ='Asia/Seoul' date '+[%I:%M %p]') 드라이브 연결 실패 ${N}회 연속" 2>/dev/null || true
  fi
  exit 1
fi
rm -f "$FAILC"
grep -viE "$EXC_RE" "$NOW.raw" > "$NOW"   # 묶음 파일 제외(위 제외 칸)
awk 'FNR==NR{s[$0]=1;next} !($0 in s)' "$SEEN" "$NOW" > "$NEW"
if [ -s "$NEW" ]; then
  LOGSZ=0
  [ -f "$LOG" ] && LOGSZ=$(wc -c < "$LOG" 2>/dev/null | tr -d ' ')
  [ -n "$LOGSZ" ] || LOGSZ=0
  if rclone copy "$REMOTE" "$LOCAL" --files-from "$NEW" --inplace --multi-thread-streams 0 \
      --contimeout 15s --timeout 60s --transfers 4 --log-file "$LOG" --log-level INFO; then
    cat "$NEW" >> "$SEEN"
    rm -f "$CPFAIL"
  else
    # ⓒ 부분 성공 정산 — 로컬에 실제로 떨어진 것만 장부에 넣고, 안 온 것만 다음 틱 재시도
    : > "$MISS"
    while IFS= read -r f; do
      [ -n "$f" ] || continue
      if [ -s "$LOCAL/$f" ]; then
        printf '%s\n' "$f" >> "$SEEN"
      else
        printf '%s\n' "$f" >> "$MISS"
      fi
    done < "$NEW"
    DN=$(wc -l < "$MISS" 2>/dev/null | tr -d ' ')
    [ -n "$DN" ] || DN=0
    if [ "$DN" -gt 0 ]; then
      # ⓐ 사유 = 이번 실행분 로그 꼬리(fail-closed 3단 · 빈 사유로 나가는 경로 0)
      TL=$(tail -c "+$((LOGSZ + 1))" "$LOG" 2>/dev/null)
      RSN=$(printf '%s\n' "$TL" | grep -m1 -E 'ERROR|Failed to copy|Fatal error' | sed 's|^[0-9][0-9/:. -]*||')
      [ -z "$RSN" ] && RSN=$(printf '%s\n' "$TL" | grep -v '^[[:space:]]*$' | tail -1 | sed 's|^[0-9][0-9/:. -]*||')
      [ -z "$RSN" ] && RSN="사유 미확인 — 로그: ~/.drivesync.log"
      RSN=$(printf '%s' "$RSN" | cut -c1-160)
      # ⓑ 실패 파일 = 안 온 것 실측(배치 첫 줄 아님) + 같은 파일 연속 회차
      DF=$(head -1 "$MISS")
      N=1
      if [ -f "$CPFAIL" ]; then
        OF=$(sed -n 1p "$CPFAIL")
        OC=$(sed -n 2p "$CPFAIL")
        [ "$OF" = "$DF" ] && N=$(( ${OC:-0} + 1 ))
      fi
      printf '%s\n%s\n' "$DF" "$N" > "$CPFAIL"
      if [ "$N" -ge "$STUCK_N" ]; then
        # ⓓ 격리 — 이 한 파일이 배치 전체를 영원히 물고 있는 상태를 끊는다(이름·사유는 남긴다)
        printf '%s\t%s\t%s\n' "$(TZ='Asia/Seoul' date '+%F %T')" "$DF" "$RSN" >> "$STUCK"
        printf '%s\n' "$DF" >> "$SEEN"
        rm -f "$CPFAIL"
        DM="$DF — ${STUCK_N}회 실패로 건너뜀(목록 ~/.drivesync.stuck)"
      else
        DM="$DF"
        [ "$DN" -gt 1 ] && DM="$DF 외 $((DN - 1))건"
        [ "$N" -gt 1 ] && DM="$DM · ${N}회째"
      fi
      termux-notification --id drivesync-fail -t "드라이브싱크 실패 ⚠️" \
        -c "$(TZ='Asia/Seoul' date '+[%I:%M %p]') $DM
$RSN" 2>/dev/null || true
    else
      # 파일은 전부 도착했는데 rc만 실패 = 사용자에겐 결손 0 → 알림 대신 로그에만(가짜 빨강 방지)
      rm -f "$CPFAIL"
      echo "$(TZ='Asia/Seoul' date '+%F %T') NOTE: rclone rc!=0 but all files landed" >> "$LOG"
    fi
  fi
  termux-media-scan -r "$LOCAL"
fi
[ -x "$HOME/.termux/tasker/drive-camera-up.sh" ] && sh "$HOME/.termux/tasker/drive-camera-up.sh"
exit 0
```

**동작 요약**

```sh
#!/data/data/com.termux/files/usr/bin/sh
# ── 알림 문구 칸(운영자 조정 — 타이틀은 이 두 변수 · 내용 문구는 아래 -c 줄) ──
T_BASE="갤러리 업로드 기준선 설정 ✅"
T_UPFAIL="업로드 실패"
# ── 동기화 제외 칸(운영자 260811 "저런 압축파일은 동기화 안되게 조치해도됨 · 양방향 모두") ──
#   묶음 파일은 갤러리에 갈 이유가 0이고, 실제로 260811 사고의 진범이 드라이브 웹의
#   「여러 개 한꺼번에 받기」 산출물 `drive-download-*.zip`이었다(256M 초과 → 갈래받기 발동).
#   ⚠ **셸 축으로 거른다**(rclone `--exclude` 아님) = `--files-from` 목록을 주는 순간 rclone 필터는
#   우회되므로 목록을 만드는 자리에서 빼야 양쪽 다 확실하다.
#   ⚠ 짝 = `drive-gallery-sync.sh`의 `EXC_RE` **동값 유지**(한쪽만 고치면 반대 방향이 조용히 샌다).
#   늘리려면 이 한 줄에 확장자만 추가(대소문자는 -i가 흡수).
EXC_RE='\.(zip|rar|7z|tar|gz|tgz|bz2|xz|zst|iso|dmg|apk|exe)$'
REMOTE_BASE="gdrive:Shared"
SRCS="/sdcard/DCIM/Camera /sdcard/DCIM/Screenshots /sdcard/Pictures/Screenshots"
WIFI_ONLY=0
UPSEEN="$HOME/.driveup.seen"
DSEEN="$HOME/.drivesync.seen"
UNOW="$HOME/.driveup.now"
UNEW="$HOME/.driveup.new"
LOG="$HOME/.driveup.log"
STAMP="$HOME/.driveup.last"
LOCK="$HOME/.driveup.lock"
T=$(date +%s)
if [ -f "$STAMP" ] && [ $((T - $(cat "$STAMP"))) -lt 120 ]; then exit 0; fi
echo "$T" > "$STAMP"
if ! mkdir "$LOCK" 2>/dev/null; then
  A=$((T - $(stat -c %Y "$LOCK" 2>/dev/null || echo 0)))
  [ "$A" -lt 7200 ] && exit 0
  rmdir "$LOCK" 2>/dev/null; mkdir "$LOCK" 2>/dev/null || exit 0
fi
trap 'rmdir "$LOCK" 2>/dev/null' EXIT
: > "$UNOW"
for SRC in $SRCS; do
  [ -d "$SRC" ] || continue
  ls "$SRC" | while IFS= read -r f; do
    [ -f "$SRC/$f" ] && printf '%s\n' "$SRC/$f"
  done >> "$UNOW"
done
grep -viE "$EXC_RE" "$UNOW" > "$UNOW.f" 2>/dev/null; mv "$UNOW.f" "$UNOW"   # 묶음 파일 제외(위 제외 칸)
[ -s "$UNOW" ] || exit 0
if [ ! -s "$UPSEEN" ]; then
  cp "$UNOW" "$UPSEEN"
  termux-notification --id driveup -t "$T_BASE" \
    -c "지금부터 새로 생기는 사진·영상만 드라이브로 올라감" 2>/dev/null || true
  exit 0
fi
awk 'FNR==NR{s[$0]=1;next} !($0 in s)' "$UPSEEN" "$UNOW" > "$UNEW"
[ -s "$UNEW" ] || exit 0
if [ "$WIFI_ONLY" = 1 ]; then
  termux-wifi-connectioninfo 2>/dev/null | grep -q '"supplicant_state": "COMPLETED"' || exit 0
fi
FAIL=0
FAILN=0
FAILF=""
for SRC in $SRCS; do
  [ -d "$SRC" ] || continue
  grep "^$SRC/" "$UNEW" | sed "s|^$SRC/||" > "$UNEW.d"
  [ -s "$UNEW.d" ] || continue
  cat "$UNEW.d" >> "$DSEEN"
  if rclone copy "$SRC" "$REMOTE_BASE" --files-from "$UNEW.d" --inplace \
      --transfers 2 --log-file "$LOG" --log-level INFO; then
    sed "s|^|$SRC/|" "$UNEW.d" >> "$UPSEEN"
  else
    FAIL=1
    FAILN=$((FAILN + $(wc -l < "$UNEW.d")))
    [ -z "$FAILF" ] && FAILF=$(head -1 "$UNEW.d")
  fi
done
if [ "$FAIL" = 1 ]; then
  FM="$FAILF"
  [ "$FAILN" -gt 1 ] && FM="$FAILF 외 $((FAILN-1))건"
  termux-notification --id driveup-fail -t "$T_UPFAIL" \
    -c "$(TZ='Asia/Seoul' date '+[%I:%M %p]') $FM" 2>/dev/null || true
fi
exit 0
```

## 2. rclone 설정 (폰)

- 리모트 이름 = **`gdrive`**, 백엔드 = Google Drive. `gdrive:` 루트 = **내 드라이브**.
- 스크립트가 보는 경로 = `gdrive:Shared` = **내 드라이브/Shared**.
- 최초/재설정: `rclone config` → `n`(new) → 이름 `gdrive` → `drive` → 클라이언트ID 비움 → scope는 **`drive`(전체) 필수**(v1.2 역방향 업로드부터 — 구 안내의 `drive.readonly`는 다운 전용 시절 것, readonly면 업로드 403) → 브라우저 인증.
- **업로드 권한(스코프) 확인**: `rclone config show gdrive | grep scope` — `drive.readonly`로 나오면 `rclone config update gdrive scope drive` → `rclone config reconnect gdrive:`(브라우저 동의 1회). scope 줄이 아예 없으면 기본 = 전체(통과). ⚠ **`config show/update`는 콜론 없이 `gdrive`** — 콜론 붙이면 `Fatal error: config name contains invalid characters`(260720 실증) · 콜론 쓰는 건 `reconnect gdrive:`·`lsf gdrive:` 같은 원격 경로 계열만.
- **토큰 만료 재연결**: `rclone config reconnect gdrive:` (브라우저 동의 다시).
- ✅ **(260720 전환 완료) 자체 client_id 가동 — 공용 은퇴 폭탄 해제**: 260719 NOTICE "retired during 2026" 예고에 이어 260720 아침 **공용 프로젝트(projects/202264815644) `RATE_LIMIT_EXCEEDED` 실측**(전 세계 공용 분당 정원 초과 → lsf가 수 분씩 무음 행 = "조용히 안 옴"의 진범) → 폰 리모트를 **운영자 자체 client_id**(GCP 프로젝트 `nomute-rclone` · 데스크톱 앱 · 동의화면 **프로덕션 게시**)로 전환, 00:42:45Z Got code 재인증 완료. 재발급·재전환 절차(콘솔 8단계·복사버튼) = `docs/reports/20260720_081451_클라이언트ID전환_가이드_v1.html`: 발급 후 `rclone config update gdrive client_id <ID> client_secret <SECRET>` → `rclone config reconnect gdrive:`(동의 1회).
  - ⚠ 실전 함정 4종(260720 실증): ① `config update/show`에 `gdrive:` 콜론 = Fatal error(위 항) ② **동의화면 '테스트' 상태 = 로그인에서 403 access_denied 전면 차단**(프로덕션 게시로 해소 · 테스트 유지 시 토큰 7일 만료 함정도 동일 축) ③ 모바일 콘솔의 클라이언트 상세 = 이름 편집 폼만 떠서 보안 비밀이 안 보임 → 클라이언트 삭제·재생성 후 **생성 직후 팝업에서 즉시 복사**(또는 데스크톱 사이트 모드) ④ `Waiting for code...` 대기 중이면 화면의 `127.0.0.1:53682/auth?state=…` 링크를 나중에 열어도 유효(프로세스 생존 시).

## 4. PC 설정 (두 PC 통일 = 재발 방지의 핵심)

**목표**: 두 PC가 **같은 폴더 `내 드라이브/Shared`** 에 저장 → 폰 rclone이 한 곳만 보면 됨.

각 PC에서:
1. **Google Drive for Desktop** 설치 → 로그인.
2. 설정에서 그 다운로드 폴더를 **"이 컴퓨터 폴더 백업"에서 빼고**, **"내 드라이브" 스트리밍**을 켠다 → 탐색기에 `G:\내 드라이브\Shared`(가상 드라이브)가 보이게.
3. 다운로더(Seal / gallery-dl 등) **저장 위치를 `G:\내 드라이브\Shared`로 지정**.
4. 확인: 그 PC에서 파일 하나 저장 → 폰에서 `rclone lsf gdrive:Shared`에 뜨면 성공.

**⚠️⚠️ 절대 규칙 — "컴퓨터 백업" 금지.** 드라이브 데스크톱의 "이 컴퓨터 폴더 백업"으로 저장하면 파일이 **드라이브 "컴퓨터" 탭**(내 드라이브 아님)으로 가고, **rclone `gdrive:`(내 드라이브)는 그걸 못 본다** → 폰에 안 내려옴. 이게 2026-07-02 "떨어져 나감"의 근본 원인이었다(두 PC가 각각 컴퓨터-백업으로 저장해 `내컴퓨터/Shared`·`내컴퓨터/다운로드2/Shared`로 갈라짐). **두 PC 다 반드시 "내 드라이브 스트림".**

옛 컴퓨터-백업 잔재(`내컴퓨터/Shared`, `다운로드2/Shared`)는 백업 해제하거나 삭제해 헷갈림을 없앤다.

### 2026-08-11 — "계속 실패하는데 이유를 모르겠다" = 알림이 사유를 안 말한 것 (v1.6 개정 계기)

### 2026-08-11 (2) — 진범 = 큰 파일 갈래받기 (v1.7 개정 계기)
- **v1.6이 그 자리에서 답을 뱉었다**(봉합 다음 실행 · 운영자 폰 실측): `drive-download-20260811T121058Z-1-001.zip: Failed to copy: multi-thread copy: failed to find object after copy: object not found`.
- **정체**: rclone은 `--multi-thread-cutoff`(기본 256M)를 넘는 파일만 여러 갈래로 쪼개 받는다. 다 쓴 뒤 대상 객체를 다시 조회해 검증하는데, 안드로이드 `/sdcard`는 FUSE 에뮬레이트 계층이라 방금 쓴 파일의 즉시 조회가 어긋나 `object not found`가 된다.
- **「완전 말짱하고 건드리지도 않았는데 갑자기」의 답**: 코드·설정·인증·회선 전부 무변경이고 **입력이 바뀌었다**. 평소 사진·영상은 문턱 아래라 단일 스트림 경로로 조용히 돌았고, 드라이브 웹의 「여러 개 한꺼번에 받기」 산출물(`drive-download-*.zip`)이 `Shared`에 올라온 **그 순간부터** 그 파일 하나에만 다른 코드 경로가 켜졌다. v1.5의 ⓒ(부분 성공 통째 폐기)와 곱해져 배치 전체가 3분마다 영구 반복이 됐다.
- **조치**: `--multi-thread-streams 0` + **묶음 파일 양방향 제외**(운영자 260811 「저런 압축파일은 동기화 안되게 · 양방향 모두」 = 재발 원천 차단 · 갈래받기 비활성은 다른 대용량 파일을 위한 이중 방어로 잔존). ⚠ 대안 폐기 = `--multi-thread-cutoff` 상향은 문턱만 미루는 미봉(더 큰 파일에서 재발) · `--transfers`는 **파일 병렬 수**라 이 축과 무관(줄여도 갈래받기는 켜진다). 속도 손해 = 큰 파일 하나의 받기 속도만 낮아진다(폰 회선에선 체감 0 · 「안 받아지는 것」보다 싸다).
- **짝(장부 오염)**: 사고 회차에 rclone이 최종 rc=0을 반환했다면 v1.5가 그 zip을 「받았다」로 등재했을 수 있다 = 영영 안 온다(260702·260719와 같은 병) → `drivesync-fix.sh` ②단이 **로그가 이름을 댄 실패 파일만** 로컬 실존 대조해 회수한다(전량 리셋 = 재다운로드 폭탄이라 금지 · `.bak` 선백업).
- **부수 봉합 2건**(운영자 화면에서 드러남): ⓐ `drivesync-fix.sh`의 `wc -l < "$MISS"` = 파일 부재 시 **리다이렉션 실패**라 `sh: 76: cannot open …`이 화면에 뜨고 결과가 빈 칸이 됐다(`2>/dev/null`은 wc의 stderr만 막지 셸의 리다이렉션 실패는 못 막는다) → `cnt()` 가드 ⓑ 진단에 rclone 판 표기 0 → `rclone version` 첫 줄 추가.
- **교훈**: v1.6의 값어치가 여기서 증명됐다 — 「사유를 갖고 나가는 경보」 하나로 6주 걸릴 추적이 **한 번의 실행**으로 끝났다. 사유가 없던 v1.5였다면 이번에도 추측 처방(재인증·SEEN 리셋)으로 갔을 것이고 전부 빗나갔을 것이다(그 셋은 이 파이프라인에서 이미 실패한 처방들이다).
