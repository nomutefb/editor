## 3. 옮기는 순서

1. **새 깃허브 계정 만들기** — 결제 등급을 하나라도 올려두면 자동 차단 판정에 덜 걸린다.
2. **빈 저장소를 새 계정에 만든다** (이름은 지금과 같아도 되고 달라도 된다)
3. **코드를 밀어넣는다**
   - 이력까지 통째로: `git remote add new https://github.com/<새계정>/<저장소>.git && git push new main`
   - 이력 없이 지금 상태만(권장): `rm -rf .git && git init && git add -A && git commit -m "이전" && git branch -M main && git remote add origin <새주소> && git push -u origin main`
4. **열쇠 38개를 새 저장소 비밀값 칸에 넣는다** (1번 목록)
5. **설정값 31개를 넣는다** (2번 목록)
6. **화면 배포를 새 저장소로 다시 연결한다** — 클라우드플레어 쪽에서 연결을 끊고 새 저장소로 다시 건다. 새로 발급되는 배포 훅 주소를 4번의 `CF_DEPLOY_HOOK` 에 덮어쓴다.
7. **파일 보관소는 안 옮긴다** — 그쪽은 깃허브 계정과 무관하므로 열쇠만 그대로 다시 넣으면 된다.
8. **15분 시계 다시 걸기** — 외부 시계 서비스(cron-job.org)의 대상 주소를 새 저장소로 바꾸고, 꺼져 있던 잡을 다시 켠다.
9. **내 컴퓨터·폰의 대체 레인 주소 갈아끼우기** — 각 기기에서 `git remote set-url origin <새주소>`
10. **검증** — 저장소의 자동화 탭에서 수집 하나를 손으로 발사해 초록으로 끝나는지 본다.

## 4. 안 옮겨도 되는 것
- 파일 보관소와 공개 주소 (다른 회사 계정)
- 화면 도메인 (연결만 새 저장소로 옮기면 주소는 유지)
- 요약·카드 산출물 (저장소 안에 있으므로 코드와 같이 따라감)

## 5. 주의
- 이력을 통째로 옮기면 커밋 3만 건과 브랜치 수백 개가 같이 간다. 그게 지금 계정이 막힌 원인으로 의심되는 자동화 규모의 흔적이라, 새 계정에서도 같은 판정을 부를 수 있다.
- 옮기기 전에 자동 커밋을 줄이는 손질을 같이 하는 게 안전하다. 15분마다 도는 시계 13개 중 몇 개는 30분·1시간으로 늘려도 화면 신선도가 거의 안 변한다.
