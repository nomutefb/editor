⚠ 왜 이게 제일 크냐

클러스터가 만드는 cross(교차 매체 수)·burst(동시 보도 속도)·arts(묶음 크기)는 지금도 라이브에서 쓰인다 — 수집함 진입(scFast cross≥2) · 랭킹 가중 · 속보 1차 게이트(burst ≥ BREAKING_BURST) · 재채점 큐(REGRADE_MIN_CROSS). 절반이 오염돼 있으면 그 숫자 전체가 부풀려져 있다. 무관한 기사 3건이 붙어 「4개 매체가 쓴 중요한 사건」으로 보인다.
이 축을 보는 게이트가 하나도 없다. check_refs 106개는 정적 문자열·경로 실존이고, smoke_*는 화면 렌더다. 「묶음이 옳은가」는 축 자체가 없어서, 운영자 눈에도 안 보인다(화면엔 대표 제목만 뜨니까).

⚠ 회귀 도장이 이미 거짓말을 하고 있다

check_rubric_regress·check_grade_regress는 스탬프 해시 대조만 한다. 실행기가 n=1이라 초록이 나올 때까지 다시 돌리면 도장이 찍히고, 빨간 기록은 어디에도 안 남는다. 실제로 이 세션에서 grade 회귀가 1차 FAIL → 2차 PASS로 도장이 갱신됐다(내용 동일·ts만 변경 → 근거 없어 되돌림).
두 번째 사각 — 도장은 RUBRIC 문자열만 해싱한다(RUBRIC_VER = sha256(RUBRIC)[:12]). 프롬프트 조립부(judge()의 listing)를 바꾸면 해시가 안 바뀌어 회귀 0회로 라이브에 나간다. 킬테스트로 확인됨(형제 배선 심고 check_refs 110게이트 전건 rc=0).

§4 검증했으나 반영하지 않은 것 — 형제 제목 병기

가설 = 「같은 사건으로 묶인 다른 기사 제목을 같이 주면 부실한 제목도 정확히 판정된다」(운영자 260810 «기자들이 타이틀을 못 뽑는다»).

A/B 설계

표본 = 오늘 12시간치 재수집 → 클러스터 대표 175건 → 형제 제목 3개+ 확보 94건 → 무작위 30건(seed 7)
A안 = 대표 제목만 (현행)
B안 = 대표 제목 + 〔같은 사건 다른 매체 제목: "…" / "…" / "…"〕 형제 3개
대조군 = A안을 동일 입력으로 2회 더 실행 (노이즈 바닥 측정)

§5 다음 세션 착수 순서 (권고)

순서를 지켜야 하는 이유 + A/B를 실제로 가능하게 하는 설계

지금은 무슨 개선을 넣어도 노이즈(4.22%)에 묻혀 좋아졌는지 나빠졌는지 잴 수가 없다. 기대 효과가 0.9%라 노이즈가 효과의 4.7배다. 그리고 프롬프트 조립을 바꾸면 회귀가 안 울린다. 측정 가능성부터 복구하지 않으면 이후 모든 개선이 검증 불가 변경이 된다.

전수 A/B는 불가능하다 — 0.9%를 잡으려면 팔당 4,141건(노이즈까지 추정하면 8,300건)이고 스냅샷당 표본이 94건이라 44회분이다.
유일하게 되는 설계 = 경합 건만 재기. 두 번 돌려 답이 갈린 건(4.2%)만 평가하면 그 안에서 효과 크기가 21%p로 커져 경합 41건(원자료 963건 = 스냅샷 10회분)이면 판정이 난다. 100배 싸진다.

[2순위] 배치 구성 고정 — 공짜이고 효과가 가장 확실한 유일한 수단. 실측상 같이 채점되는 이웃 제목이 판정을 바꾼다(배치30 vs 배치10 다수결 답이 5/30 다름). ⚠ 배치 축소는 거꾸로 간다(4.22% → 14.44%) — CHUNK를 낮추지 마라. 3회 다수결도 21% 감소에 비용 3배라 효율이 나쁘고, 추론 강도 부여는 노이즈만 2배로 늘린다(다수결 답 0/30 동일 = 둘 다 기각). 지금 문제는 정렬이 first_seen 내림차순이라 매 런 이웃이 바뀐다는 것(gate_judge.py:359) → 같은 건이 어제와 다른 이웃과 채점된다. 결정적 배치 키(예: 카테고리·해시 버킷)를 넣으면 재현성이 오른다
  3. [3순위] 회귀 도장 사각 봉합 — ⓐ RUBRIC_VER를 RUBRIC + inspect.getsource(judge)로 확장(조립부가 해시에 들어가야 한다) ⓑ 실행기를 k회 반복·전건 통과로 바꾼다(n=1이면 도장은 계속 코인플립) ⓒ 실패 회차를 원장에 남긴다(지금은 재실행하면 기록이 사라진다)
  4. [4순위] 판정 재료 보강 — 형제 제목이 아니라 「본문 첫 문단」. 이미 수집돼 있다 — 전체의 92.2%가 보유하고 중앙 200자다. 추가 수집·추가 콜 0이고, 판정에 새 사실이 들어가는 유일한 안이다(형제 제목은 같은 말의 반복인 경우가 많았다). 형제 제목 병기를 굳이 다시 잰다면 정제 규칙 필수 = 고유명사 1개 이상 공유할 때만(무관 5건이 전부 이 술어에서 걸린다) + 정형구 클러스터 금지(실적·시황·수주·시상 — 새 정규식 창작 0, REGRADE_BIZ_RE/REGRADE_MKT_RE 재사용) + 개수를 문장으로 노출 금지 + 저장은 candidates.json 금지, 사이드카 파일
  5. [별건] 수집 정지 — 오늘 16:07 이후 last_seen이 갱신되지 않았다(수동 디스패치 2회에도 불변). 원인 미확인. 정연 건이 승격 창을 놓친 직접 원인이고, 방치하면 뉴스 유입 자체가 멈춘다

# ② 대표 + 형제 제목 풀 추출
python3 - <<'EOF'
import json
arts=json.load(open('/tmp/ab/articles.json'))
arts=list(arts.values()) if isinstance(arts,dict) else arts
byl={a['link']:a for a in arts if a.get('link')}
rows=[]
for a in arts:
    if not a.get('is_cluster_rep') or not (3<=(a.get('cluster_size') or 0)<=40): continue
    sib=[byl[u]['title'] for u in (a.get('cluster_members') or [])
         if u in byl and u!=a.get('link') and byl[u].get('title')!=a.get('title')]
    if len(sib)>=3: rows.append({'title':a['title'],'sib':sib,'cross':a.get('cross_score')})
json.dump(rows,open('/tmp/ab/pool.json','w'),ensure_ascii=False); print(len(rows))
EOF

# ③ 채점기 직접 호출 (A/B · 노이즈 측정 공용)
python3 - <<'EOF'
import importlib.util, json
s=importlib.util.spec_from_file_location('gj','.github/scripts/gate_judge.py')
gj=importlib.util.module_from_spec(s); s.loader.exec_module(gj)
pool=json.load(open('/tmp/ab/pool.json'))[:30]
A=[(str(i),r['title']) for i,r in enumerate(pool)]
B=[(str(i), r['title']+' 〔같은 사건 다른 매체 제목: '+' / '.join('"%s"'%t for t in r['sib'][:3])+'〕')
   for i,r in enumerate(pool)]
g1,_,_,rc,_=gj.judge(A); g2,_,_,_,_=gj.judge(A)   # 노이즈 = g1 vs g2
gb,_,_,_,_=gj.judge(B)                            # 효과 = g1 vs gb (단 노이즈보다 커야 유의)
print('noise', sum(1 for k in g1 if g1[k]!=g2.get(k)), '/ effect', sum(1 for k in g1 if g1[k]!=gb.get(k)))
EOF
