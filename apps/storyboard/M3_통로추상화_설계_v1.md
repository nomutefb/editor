## 1. 선결 봉합 — 비율 전달 (이번 커밋에 반영 완료)

**실사고(무증상)**: 콘티 머리는 `비율: 16:9` 를 선언하는데 러너가 그 줄을 **한 번도 읽지 않았다**. 통로 기본값(가로)으로 상시 발사됐고, 참조 그림은 세로(레퍼런스 기본 `9:16`)로 굽고 있었으므로 **그림은 세로 · 영상은 가로**로 갈린 채 살아 있었다. 260812 실측 산출 전건 1280×720(가로).

증상이 0인 이유 = 지금까지 콘티가 전부 `16:9` 를 적어서 **우연히 기본값과 같았다.** 쇼츠(세로)가 산출 규격이 되는 순간 「세로로 만들 방법이 코드에 없는」 상태가 그대로 드러난다.

봉합 = `ratio_of(md)` 가 콘티 선언을 읽어 발사에 전달. 값 창작 0(콘티가 적은 값 그대로) · 통로가 못 받는 값이면 기본값으로 내려앉되 **사유를 남긴다**(조용한 강등 금지) · `video.json` 에 `ratio` 기록. 게이트 3축 동반.

⚠ **남은 것** = 콘티 규약이 아직 가로를 기본으로 쓴다. 쇼츠 전환은 §5-④에서 규약과 함께 간다.

## 2. 통로 경계 — 무엇이 통로 몫인가

### 2-1. 직접 호출 5종 (설계안 그대로 유효)

자격 받기 · 발사 · 완료 기다리기 · 결과 바이트 받기 · 실패 예외.

### 2-2. 간접 결합 — 통로로 넘겨야 하는 것 (검증이 추가로 찾은 자리)

| 자리 | 지금 모양 | 왜 통로 몫인가 |
|---|---|---|
| 참조 **수송** | 바이트 임베드 + 몸집 거절 시 주소 폴백 | 힉스필드는 **주소 직전달 금지**(올려서 받은 번호만) → 형태가 다르다 |
| 재시도 **술어** | 예외 필드 직독(검열·자격·통로) | 실패 생김새가 벤더마다 다르다 |
| 재시도 **전제** | 「실패한 호출은 청구 0」 | **그록 실측이지 힉스필드 실측이 아니다** — 환불 여부 미확인 |
| 사유 사전 | 예외 5필드 → 사람말 | 통로마다 실패 모양이 다르다 |
| 프롬프트 **문법 훅** | 참조 태그 · 소리 절 | 그록 공식 문법. 시댄스 수용 여부 미확인 |
| 소리 처리 | 프롬프트 4수법 + 산출 트랙 제거 | 시댄스는 소리 파라미터 축이 따로 있다 |
| 값 원장 | 벤더명 리터럴 + 실청구 표기 | 그록은 달러 실청구, 힉스필드는 크레딧 견적 |
| 과금 단위 판별 | 청구 실값 전제 | 크레딧 벤더에선 다른 판별 |
| 컷 초 클램프 | 엔진 상한 15 | 시댄스 2.5는 30 |
| 자격 수명 | 토큰 1회 취득 후 전 편 재사용 | 수명·갱신 축이 통로마다 다르다 |

### 2-3. 진짜 통로 무관 (그대로 재사용)

컷 파싱 · 편 묶기 골격 · 참조 슬롯 선택(밤낮) · 슬롯 번호 재부여 · 이어붙이기 · 결과 레일 착지 · 실패 알림 골격 · 값 원장 골격.

## 3. 통로가 들고 있어야 할 값·정책

**상수 7** = ① 발사 단위 초 ② 엔진 허용 상한 초(①과 **다른 값**) ③ 비율 지원 목록 ④ 해상도 옵션 ⑤ 참조 장수 기술 상한 ⑥ 수송 몸집 상한 ⑦ 폴링 간격·총상한.

**정책 메서드 5** = ⑧ 참조 수송 방식 ⑨ 소리 처리 방식 ⑩ 과금 모양(실청구/견적·단위) ⑪ 실패 시 과금 여부 ⑫ 오류 분류 술어.

**예외 3속성 공통 계약** = `재시도 가능 축` · `자격 축` · `사람말 사유 + 원문`. 러너 분기가 이 속성명으로만 갈리면 통로 무관이 된다. **크레딧 부족은 제3의 축으로 신설**한다 — 자격도 통로도 살아 있는데 돈이 없는 상태이고, 조치가 「재승인」도 「통로 교체」도 아닌 「충전」이라 기존 두 축 어디에도 안 들어간다.

## 4. 힉스필드 창구 고유 축 (현행 스키마 실측)

1. **무제한 사용 여부를 명시 안 하면 잡이 제출되지 않는다.** 미전달이면 서버가 「무제한을 쓸까요」를 되묻고 **아무것도 안 쏜다** — 헤드리스 러너가 이 응답형을 모르면 무성 무산출이 초록으로 통과한다. 계약 = **항상 명시 전달**. ⚠ M2 §4의 「항상 미전달」 규칙은 현행 스키마와 정면 충돌 = 낡음.
2. **길이가 조용히 바뀐다.** 지원 밖 길이는 오류가 아니라 **가까운 값으로 클램프되어 통과**한다 → 그록의 「서버가 실제로 만든 길이를 요청값과 대조」 축이 필수.
3. **참조는 주소 직전달 금지.** 올려서 받은 번호로만 받는다. 주소를 넘기면 힉스필드 서버가 우리 저장소를 내려받는 구조가 되어 **260812와 같은 실패 종류가 한 층 더 생긴다** → 바이트 직접 올리기가 구조적 해소안(그록 봉합과 방향 동일).
4. 기다리기 호출이 회당 상한이 있어 **반복 호출 + 총상한**이 러너 몫이다. 상한 없이 붙이면 큐 고착이 잡 시간을 통째로 태운다.
5. **인증** = 표준 OAuth. 동적 등록 · 갱신 열쇠 · `offline_access` · PKCE + **기기 코드 흐름**이 별도 호스트에 있고 「리다이렉트를 못 받는 클라이언트용」으로 명시 → **클로드 세션 경유가 필수가 아니다.**

## 5. 5단계 진행 (①② = 결제 전 · 돈 0)

**① 통로 계약 신설** — 5직접 + 10간접을 통로 뒤로. 예외 3속성 계약. 그록 통로를 그 계약의 첫 구현으로 되맞춤. 게이트·스모크로 그록 레인 무회귀 확인.

**② 힉스필드 통로 파일** — 기기 코드 승인 1회 → 갱신 열쇠 → 비밀값 되쓰기 → 이후 자동. 견적을 **발사 전 예산 검문**으로.

**③ 첫 실호출** — **15초 한 발**로 시작. 잴 것 = 대기 시간 · 품질 · 세로 · 소리 · 실패 시 환불 여부 · 실패 응답 생김새.

**④ 30초 한 발 승격 + 콘티 규약 세로 30초로** — §6 참조.

**⑤ 기존 배선 물리기** — 결과 레일 착지 · 값 표기 · 실패 알림.

## 6. 콘티 규약이 반드시 바뀌어야 하는 이유

「편 길이 = 10초 · 컷 초 합 = 10의 배수」가 규약·화면·게이트·러너 4면에 박혀 있다. 일반화 = 「편 길이 = 그 촬영 레인의 한 발 길이 · 컷 초 합 = 그 배수」.

⚠ **함정** = 시댄스 2.0(한 발 15초)이 일반해를 깬다. 30은 10의 배수라 10초 보드를 30초 발로 재묶을 수 있지만 **15는 아니다**. 즉 15초 발이 실재하면 **콘티가 레인 종속 산출물**이 된다(같은 콘티를 레인만 바꿔 재발사 불가). 이 사실을 규약에 명시해야 다음 세션이 「콘티는 공통 상류」로 오독하지 않는다.

⚠ 사건 밀도 지침(「한 편에 사건 1~2개」)은 10초 편 기준이다. 30초 편 밀도는 **복사하지 말고 따로 정한다**.

## 7. 운영자 확정 (260812 · M2 미결 2건 종결)

### 7-1. 승인 = **2단** (운영자 260812 확정)

```
소스 투입 → [1차 승인 버튼] → 페이블 콘티 + 제미나이 참조 그림 + 시트 → **멈춤**
          → 운영자가 스토리보드를 본다 → [2차 승인 버튼(최종)] → 영상 발사
```

⚠ **이 결정이 곧 「발사를 둘로 나눈다」는 뜻이다.** 현행은 한 잡 안에서 콘티→참조→시트→영상이
연속으로 가고, 촬영이 그록이면 **콘티가 나오자마자 멈추지 않고 그대로 쏜다** — 스토리보드를 볼
창이 구조적으로 없다. 2차 승인을 넣으려면 그 자동 연쇄를 끊어야 한다.

→ **잡 분리**(M2 미결 ⓑ 종결) = 콘티 잡(현행) + **영상 전용 잡**(신설 · 기존 `sb_out/<id>/board.md`
를 입력으로 받아 영상만 쏜다 · 통로 선택 = 그록·시댄스 공용). M2의 「별도 잡」 방향은 맞았으나
**시댄스 전용이 아니라 통로 무관 영상 잡**이라는 점이 다르다.

⚠ **덤으로 두 구멍이 같이 막힌다** = ⓐ 「실패한 그 편만 다시 쏘기」(260812 버스하우스에서 못 한 것 —
현행은 전체 재발사라 콘티부터 새로 나온다) ⓑ 「같은 콘티로 통로만 바꿔 재발사」(그록으로 시행착오를
줄이고 그 콘티 그대로 시댄스로 넘기는 운영자 전략이 구조로 성립).

⚠ 2차 승인 버튼 옆에 **견적 표기**(힉스필드는 제출 없이 크레딧만 회신) = M2 §4 G2가 요구한
「견적 → 승인 → 실발사」가 정확히 이 자리에서 성립한다. 돈이 나가는 유일한 문 앞이다.

### 7-2. 기본 프리셋 3종 (운영자 260812 확정 · 산출 = 세로 30초 쇼츠 고정)

| 프리셋 | 통로·모델 | 해상도 | 한 발 | 발 수 | 크레딧 합 | 울트라 연간 6천 기준 |
|---|---|---|---|---|---|---|
| A | 시댄스 2.5 | 720p | 30s | **1** | 195 | $4.06 |
| B | 시댄스 2.0 표준 | **1080p** | 15s | **2** | 270 | $5.63 |
| C | 그록 | 720p | 10s | **3** | (구독 = 크레딧 0) | 0 |

하루 1편 기준 월 크레딧 = A 5,850(6천 티어 딱) · B 8,100(9천 티어 필요) · C 0.
A = 이음매 0 · B = 화질 최상 · C = 시행착오 베드(운영자 구독으로 사실상 공짜).

### 7-3. ⚠ 이 프리셋이 콘티 레인 종속을 **해소한다** (§6의 우려 종결)

§6은 「시댄스 2.0(15초)이 10의 배수 계약을 깨서 콘티가 레인 종속이 된다」고 판정했다.
**30초 고정이 그 문제를 없앤다** — 30은 10·15·30 **전부의 배수**다.

성립 조건 = 콘티가 **10초·15초·20초 지점에 컷 경계를 반드시 둔다**(그 사이에 컷이 더 있어도 무관).
그러면 같은 board.md 하나를 세 프리셋 전부가 재묶기 할 수 있다:
A = 0~30 · B = 0~15 / 15~30 · C = 0~10 / 10~20 / 20~30.

이 규약이 없으면 컷이 묶음 경계에 걸쳐 잘려 프리셋을 바꾸는 순간 호흡이 끊긴다.
→ **`prompts/sb-make.md` 개정 항목**(§5-④와 같은 커밋).

열쇠 회전 여부 · 기기 코드 창구가 동적 등록 열쇠를 받는지 · 액세스 토큰 수명 · 실패 응답 생김새 · **실패 시 크레딧 환불 여부** · 견적 응답에 클램프된 길이가 실리는지 · 계정과 작업공간 일치 · 시댄스 참조 장수 상한 · 시댄스가 그록 참조 태그·시각 눈금 문법을 받는지 · 크레딧→달러 환산율(요금제 종속 — **`usd` 칸에 창작 금지**).

## 10. 값 원장 함정 2건 (편입 전 봉합 대상)

ⓐ 금액을 생략하면 **벤더를 안 보고 제미나이 단가로 계산**한다 → 크레딧 지출이 제미나이 달러로 둔갑.
ⓑ 중복 제거 키가 종류 단독이라 **같은 작업을 다른 통로로 재발사하면 앞 통로 지출 기록이 소리 없이 지워진다.**
ⓒ 단위 = 힉스필드는 크레딧 과금인데 원장 칸은 달러다. 환산율은 요금제 종속이라 **지어내면 안 된다** — 크레딧 실값을 남기고 화면에 병기하는 쪽이 정직하다.
